# What retire/retire.sh takes out of a game directory, and how it recognises it. One entry a
# line, fields separated by spaces; '#' starts a comment. The release scripts keep their own
# copy of the table in awk and PowerShell (publish/package.sh bakes this file as retire.txt);
# the binaries' hashes stay here after they leave platform/vendor/.
#
#   plugin <Name>...        <Name>.asi, .ini and .log
#   plugin-dir <Dir>        <Dir>/*.bmp, then the folder if it is empty (MenuScale's plates)
#   glob <Dir> <pattern>    <Dir>/<pattern>, then the folder if it is empty
#   glob-hash <Dir> <pattern> <sha256>...
#                           like glob, but only the files whose hash is one of the listed: every
#                           version of the sky recipes any release shipped (a Sky\<name>.ini the
#                           player edited is theirs and stays)
#   file <name>             a file of the game directory the project's tooling alone wrote
#   hud-files               put back from backups (hud-files.py): the misc/ UI configs, the
#                           cursors, the font atlases, SOD/logo.SOD and the LOADING textures
#   bloom                   the per-user vkBasalt bloom, outside the game directory
#   chain-hash <file> <sha256> <what>
#                           removed only when its hash is the vendored build's (class chain)
#   chain-marker <file> <marker>
#                           removed only when it carries our marker line (class chain)
#
# The chain class is taken out only with --chain, which ./install and the release installers
# pass since platform 4.0.0 (Display8 no longer stands on d3d8to9 as d3d8_real.dll or on
# DXVK's d3d9). The binaries left platform/vendor/ then; these hashes are what is left of them.
